containix is a containerd shim that runs Nix flakes as Kubernetes pods. Your flake reference is the artifact. The shim resolves it against your binary cache, bind-mounts the closure as a rootfs, and hands off to runc — which knows nothing about Nix and doesn't need to.

shape

one annotation. one RuntimeClass. that's the API.

Pods opt into containix with a RuntimeClass. The flake reference rides along as an annotation. The image field still exists — Kubernetes demands it — but containix ignores its contents. A 49-byte empty image satisfies the contract.

That's the entire public surface area. No new CRDs. No sidecar. No webhook. The same kubectl apply, the same scheduler, the same networking.

Containix reads the annotation, resolves the flake, materializes the rootfs, writes an OCI runtime spec, and gets out of the way. 

pod.yamlapiVersion: v1
kind: Pod
metadata:
  name: my-app
  annotations:
    containix.dev/flake:      "github:org/app#default"
    containix.dev/entrypoint: "/bin/myapp"
spec:
  runtimeClassName: containix
  containers:
  - name: app
    image: "containix/empty:1.0.0"  # required, ignored
flow

annotation → closure → rootfs → runc. four steps.

  ┌─ pod ──────────────┐      ┌─ shim ────────────┐      ┌─ runc ────────────┐
  │ annotation:        │      │                   │      │                   │
  │   containix.dev/   │      │  resolve flake     │      │  standard OCI     │
  │     flake          │  →   │  fetch   closure   │  →   │  container        │
  │                    │      │  mount   rootfs    │      │  lifecycle        │
  │ runtimeClassName:  │      │  write   OCI spec  │      │                   │
  │   containix         │      │                   │      │                   │
  └────────────────────┘      └───────────────────┘      └───────────────────┘
swap

what containix replaces.

Dockerfile, base image, RUN apk add...
The flake. It already describes the closure. One source of truth.
docker build, image tagging, layer caching
A flake lock. Same input → same closure → same rootfs.
docker push, image registry, pull credentials
Your binary cache — Cachix, Attic, S3, anything that substitutes.
imagePullPolicy, ImagePullBackOff, sleep-and-retry
Closures stream from cache; shared store paths mount once per node.
"works in CI, fails in prod" image drift
No build environment. The closure you tested is the closure that runs.
latent shells, package managers, busybox surprises
Exactly the closure you declared. Nothing else.
try

kick the tires.

Containix is consumable today as a Nix flake output and as a NixOS module. The shim has been driven on a NixOS VM and a local cluster. The API will change before v1 — pin commits.

$nix run github:atmask/containix # dev shim, runs in the foreground
$go get containix.dev/pkg/nix # consume as a Go module
