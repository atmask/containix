Containix
Vol. 0 · Issue 1 v0.1.0
A containerd shim, written as a build journal github.com/atmask/containix

Reference a Nix flake. Skip the registry.

Containix is a containerd shim that resolves a flake reference into a container's rootfs at startup. No Dockerfiles. No image pushes. No layer caching. A pod points at a flake; the shim fetches its closure from your binary cache and bind-mounts it as the filesystem. Then it hands off to runc1, which knows nothing about Nix.

§ 01 The Idea

A container image is, more or less, a tarball of files plus some metadata about how to run them. Nix produces something stronger: a content-addressed closure of files plus a precise spec of how it was built. If a node already has the right Nix daemon and a path to a binary cache, the closure is mostly already there — or one fetch away.

So why are we still tarring it up, pushing it to a registry, and pulling it back down to the same node it came from?

The image was a workaround. The closure is the artifact.

Containix is one answer to that question. It slots in as a containerd shim — the same plug-in point that runc uses — reads a flake reference from the pod's annotations, materializes the rootfs from store paths, and proceeds. To Kubernetes it's a normal pod. To you it's a flake.

  1. runc is the OCI runtime that actually spawns the container after the shim assembles the spec. Containix doesn't replace it; it precedes it.
§ 02 The Flow

From annotation to running process.

   ┌─────────────────────────────┐
   │  pod spec                   │
   │  annotations:               │
   │    containix.dev/flake:     │
   │      "github:org/app#bin"   │
   └──────────────┬──────────────┘
                  │
                  ▼
   ┌─────────────────────────────┐
   │  containix shim             │
   │                             │
   │  1. resolve flake → path    │
   │  2. nix-store -qR (closure) │
   │  3. bind-mount as rootfs    │
   │  4. write OCI runtime spec  │
   └──────────────┬──────────────┘
                  │
                  ▼
   ┌─────────────────────────────┐
   │  runc                       │
   │  standard container start   │
   └─────────────────────────────┘

Fig. 1Five seconds, give or take a cache warmup.

§ 03 In Practice

A pod is a flake reference and a stub.

Two annotations and a RuntimeClass. The image field exists because the OCI spec demands one; containix ignores it. A 49-byte empty image satisfies the contract. 

apiVersion: v1
kind: Pod
metadata:
  name: my-app
  annotations:
    containix.dev/flake:      "github:myorg/myapp#default"
    containix.dev/entrypoint: "/bin/myapp"
spec:
  runtimeClassName: containix
  containers:
  - name: app
    image: "containix/empty:1.0.0"   # required by Kubernetes, unused by us
§ 04 Status

Early. Honest about it.

End-to-end: working. Test coverage on the core packages: 91.5%. Consumable today as packages.default or a nixosModule. The shim has been driven manually on a NixOS VM and on a local cluster. Real-cluster integration testing is still by hand.

The API will move before v1. Pin commits, not branches. File bugs ungracefully — the project would rather hear about them than not.
